Automation Platform

BACKEND FUNCTIONAL REQUIREMENTS

Το παρόν έγγραφο καταγράφει τις λειτουργικές απαιτήσεις του Backend ανά ενέργεια χρήστη. Κάθε Use Case μπορεί να περιλαμβάνει ένα ή περισσότερα endpoints, αλληλεπιδράσεις με βάσεις δεδομένων ή ασύγχρονες διαδικασίες. Τα αναλυτικά API contracts θα τεκμηριωθούν ξεχωριστά μέσω Swagger.

UC-001 — User Registration

1. Περιγραφή

Το Use Case περιγράφει τη διαδικασία εγγραφής νέου χρήστη στο Automation Platform. Ο χρήστης συμπληρώνει τα απαιτούμενα στοιχεία στη φόρμα εγγραφής και υποβάλλει το αίτημα. Το Backend ελέγχει την εγκυρότητα των δεδομένων και τους κανόνες μοναδικότητας και, εφόσον όλοι οι έλεγχοι ολοκληρωθούν επιτυχώς, δημιουργεί τον νέο λογαριασμό στη βάση δεδομένων.

2. Βασικά στοιχεία

ΠεδίοΠεριγραφή
Use Case IDUC-001
Use Case NameUser Registration
ActorΕπισκέπτης / Μη εγγεγραμμένος χρήστης
TriggerΥποβολή της φόρμας εγγραφής
EndpointPOST /cf_automation/users/register
Content-Typeapplication/json
PreconditionsΗ εφαρμογή είναι διαθέσιμη και ο χρήστης έχει πρόσβαση στη φόρμα εγγραφής.
Success PostconditionΔημιουργείται νέος λογαριασμός και αποθηκεύεται στη βάση δεδομένων.
Failure PostconditionΔεν δημιουργείται νέος λογαριασμός και τα υπάρχοντα δεδομένα παραμένουν αμετάβλητα.

3. Main Flow

ΒήμαActorΕνέργεια / Αναμενόμενη συμπεριφορά
1ΧρήστηςΑνοίγει τη φόρμα εγγραφής.
2ΧρήστηςΣυμπληρώνει τα απαιτούμενα προσωπικά στοιχεία και το password.
3ΧρήστηςΥποβάλλει τη φόρμα εγγραφής.
4FrontendΣτέλνει αίτημα POST /cf_automation/users/register με JSON request body.
5BackendΠαραλαμβάνει το αίτημα και ελέγχει τα υποχρεωτικά πεδία.
6BackendΕλέγχει τους κανόνες εγκυρότητας των πεδίων, όπως email, phone και password.
7BackendΕλέγχει τη μοναδικότητα του email και των υπόλοιπων πεδίων που υπόκεινται σε σχετικούς κανόνες.
8BackendΔημιουργεί τον λογαριασμό και αποθηκεύει το password με ασφαλή μη αναστρέψιμη μορφή.
9BackendΕπιστρέφει απόκριση επιτυχίας χωρίς password ή άλλα μυστικά διαπιστευτήρια.
10ΣύστημαΟ νέος λογαριασμός είναι καταχωρισμένος στη βάση δεδομένων.

4. Alternative / Error Flows

AF-REG-002Μη έγκυρο emailΗ εγγραφή απορρίπτεται.
AF-REG-003Μη έγκυρο τηλέφωνοΗ εγγραφή απορρίπτεται.
AF-REG-004Password που δεν πληροί τους κανόνεςΗ εγγραφή απορρίπτεται.
AF-REG-005Το email χρησιμοποιείται ήδηΔεν δημιουργείται δεύτερος λογαριασμός.
AF-REG-006Παραβίαση άλλου κανόνα μοναδικότηταςΔεν δημιουργείται διπλότυπος χρήστης.
AF-REG-007Μη αποδεκτό όνομα ή επώνυμοΗ εγγραφή απορρίπτεται βάσει validation.
AF-REG-008Μη έγκυρο JSON requestΤο Backend επιστρέφει κατάλληλη απόκριση αποτυχίας.
AF-REG-009Δύο ταυτόχρονες εγγραφές με ίδιο emailΔιατηρείται η μοναδικότητα του email.
AF-REG-010Αποτυχία αποθήκευσηςΔεν παραμένει μερικώς δημιουργημένος λογαριασμός.

5. Business Rules

Rule IDBusiness Rule
BR-REG-001Τα υποχρεωτικά πεδία πρέπει να συμπληρώνονται.
BR-REG-002Το email πρέπει να ικανοποιεί τον καθορισμένο RegEx κανόνα.
BR-REG-003Το τηλέφωνο πρέπει να ικανοποιεί τον καθορισμένο RegEx κανόνα.
BR-REG-004Το password πρέπει να ικανοποιεί τους κανόνες μορφής και πολυπλοκότητας.
BR-REG-005Δεν επιτρέπονται δύο λογαριασμοί με το ίδιο email.
BR-REG-006Πρέπει να τηρούνται οι υπόλοιποι κανόνες μοναδικότητας.
BR-REG-007Αποτυχημένη εγγραφή δεν πρέπει να δημιουργεί χρήστη.
BR-REG-008Το password δεν αποθηκεύεται ως plain text.
BR-REG-009Τα passwords και άλλα μυστικά διαπιστευτήρια δεν επιστρέφονται στις αποκρίσεις.

6. Backend Functional Requirements

API-REG-002Το Backend πρέπει να επικυρώνει όλα τα υποχρεωτικά πεδία εγγραφής.
API-REG-003Το Backend πρέπει να ελέγχει τη μορφή email.
API-REG-004Το Backend πρέπει να ελέγχει τη μορφή τηλεφώνου.
API-REG-005Το Backend πρέπει να εφαρμόζει τους κανόνες password.
API-REG-006Το Backend πρέπει να αποτρέπει εγγραφή με ήδη καταχωρισμένο email.
API-REG-007Το Backend πρέπει να αποτρέπει διπλότυπους χρήστες βάσει των κανόνων μοναδικότητας.
API-REG-008Αποτυχημένο Registration δεν πρέπει να δημιουργεί εγγραφή στη βάση.
API-REG-009Το password δεν πρέπει να αποθηκεύεται ως plain text.
API-REG-010Οι αποκρίσεις δεν πρέπει να εκθέτουν password ή άλλα μυστικά διαπιστευτήρια.

UC-002 — User Login

1. Περιγραφή

Το Use Case περιγράφει τη διαδικασία σύνδεσης εγγεγραμμένου χρήστη στο Automation Platform. Ο χρήστης συμπληρώνει τα διαπιστευτήριά του στη φόρμα Login και υποβάλλει το αίτημα. Το Backend ελέγχει την εγκυρότητα των στοιχείων και, εφόσον η αυθεντικοποίηση ολοκληρωθεί επιτυχώς, επιτρέπει στον χρήστη να αποκτήσει πρόσβαση στις προστατευμένες λειτουργίες της εφαρμογής. Σε περίπτωση αποτυχημένης αυθεντικοποίησης, η πρόσβαση δεν επιτρέπεται.

2. Βασικά στοιχεία

ΠεδίοΠεριγραφή
Use Case IDUC-002
Use Case NameUser Login
ActorΕγγεγραμμένος χρήστης
TriggerΥποβολή της φόρμας Login
EndpointPOST /cf_automation/users/login
Content-Typeapplication/json
PreconditionsΗ εφαρμογή είναι διαθέσιμη και υπάρχει καταχωρισμένος λογαριασμός χρήστη.
Success PostconditionΟ χρήστης αυθεντικοποιείται επιτυχώς και αποκτά πρόσβαση στις προστατευμένες λειτουργίες της εφαρμογής.
Failure PostconditionΗ αυθεντικοποίηση αποτυγχάνει και δεν παρέχεται πρόσβαση στις προστατευμένες λειτουργίες.

3. Main Flow

ΒήμαActorΕνέργεια / Αναμενόμενη συμπεριφορά
1ΧρήστηςΑνοίγει τη φόρμα Login.
2ΧρήστηςΣυμπληρώνει το αναγνωριστικό σύνδεσης και το password.
3ΧρήστηςΥποβάλλει τη φόρμα Login.
4FrontendΣτέλνει αίτημα POST /cf_automation/users/login στο Backend.
5BackendΠαραλαμβάνει τα διαπιστευτήρια και ελέγχει ότι έχουν συμπληρωθεί τα υποχρεωτικά πεδία.
6BackendΕλέγχει την ύπαρξη του λογαριασμού και την εγκυρότητα των διαπιστευτηρίων.
7BackendΟλοκληρώνει επιτυχώς την αυθεντικοποίηση.
8BackendΕπιστρέφει απόκριση επιτυχίας χωρίς να περιλαμβάνει το password του χρήστη.
9ΣύστημαΟ χρήστης αποκτά πρόσβαση στις προστατευμένες λειτουργίες της εφαρμογής.

4. Alternative / Error Flows

IDΠερίπτωσηΑναμενόμενη συμπεριφορά
AF-AUTH-001Λανθασμένο passwordΗ αυθεντικοποίηση απορρίπτεται.
AF-AUTH-002Ανύπαρκτος χρήστηςΗ αυθεντικοποίηση απορρίπτεται.
AF-AUTH-003Κενό αναγνωριστικό χρήστηΤο αίτημα απορρίπτεται λόγω validation.
AF-AUTH-004Κενό passwordΤο αίτημα απορρίπτεται λόγω validation.
AF-AUTH-005Null τιμές στα υποχρεωτικά πεδίαΤο αίτημα απορρίπτεται.
AF-AUTH-006Μη έγκυρο JSON requestΤο Backend επιστρέφει κατάλληλη απόκριση αποτυχίας.
AF-AUTH-007Πρόσβαση σε προστατευμένη λειτουργία μετά από αποτυχημένο LoginΗ πρόσβαση δεν επιτρέπεται.
AF-AUTH-008Απόκριση Login με ευαίσθητα δεδομέναΤο σύστημα δεν πρέπει να επιστρέφει password ή άλλα μυστικά διαπιστευτήρια.

5. Business Rules

Rule IDBusiness Rule
BR-AUTH-001Η σύνδεση επιτρέπεται μόνο με έγκυρα διαπιστευτήρια.
BR-AUTH-002Τα υποχρεωτικά πεδία της φόρμας Login πρέπει να συμπληρώνονται.
BR-AUTH-003Το Backend πρέπει να απορρίπτει λανθασμένα διαπιστευτήρια.
BR-AUTH-004Αποτυχημένο Login δεν πρέπει να παρέχει πρόσβαση σε προστατευμένες λειτουργίες.
BR-AUTH-005Η απόκριση Login δεν πρέπει να περιλαμβάνει το password του χρήστη.

6. Backend Functional Requirements

Requirement IDFunctional Requirement
API-AUTH-001Το Backend πρέπει να επιτρέπει Login με έγκυρα διαπιστευτήρια.
API-AUTH-002Το Backend πρέπει να απορρίπτει λανθασμένα διαπιστευτήρια.
API-AUTH-003Το Backend πρέπει να ελέγχει τα υποχρεωτικά πεδία του Login.
API-AUTH-004Αποτυχημένο Login δεν πρέπει να παρέχει πρόσβαση σε προστατευμένες λειτουργίες.
API-AUTH-005Η απόκριση Login δεν πρέπει να περιλαμβάνει password.

UC-003 — User Profile Update

1. Περιγραφή

Το Use Case περιγράφει τη διαδικασία ενημέρωσης των προσωπικών στοιχείων ενός εγγεγραμμένου χρήστη στο Automation Platform. Ο αυθεντικοποιημένος χρήστης ανοίγει τη σελίδα My Profile, τροποποιεί τα επιτρεπόμενα στοιχεία του και υποβάλλει τις αλλαγές. Το Backend ελέγχει την αυθεντικοποίηση, την εγκυρότητα των νέων δεδομένων και τους κανόνες μοναδικότητας και ενημερώνει τον λογαριασμό. Το First Name (Όνομα) και το Last Name (Επώνυμο) δεν επιτρέπεται να τροποποιούνται μετά την εγγραφή, ακόμη και αν αποσταλούν διαφορετικές τιμές μέσω API.

2. Βασικά στοιχεία

ΠεδίοΠεριγραφή
Use Case IDUC-003
Use Case NameUser Profile Update
ActorΑυθεντικοποιημένος χρήστης
TriggerΥποβολή αλλαγών από τη σελίδα My Profile
EndpointPUT /cf_automation/users/update
Content-Typeapplication/json
PreconditionsΟ χρήστης έχει πραγματοποιήσει επιτυχημένο Login και έχει πρόσβαση στο προφίλ του.
Success PostconditionΤα επιτρεπόμενα στοιχεία ενημερώνονται και αποθηκεύονται στη βάση. Το First Name και το Last Name παραμένουν αμετάβλητα.
Failure PostconditionΤα προηγούμενα στοιχεία παραμένουν αμετάβλητα.

3. Main Flow

ΒήμαActorΕνέργεια / Αναμενόμενη συμπεριφορά
1ΧρήστηςΑνοίγει τη σελίδα My Profile.
2ΣύστημαΕμφανίζει τα αποθηκευμένα στοιχεία του χρήστη.
3ΧρήστηςΤροποποιεί επιτρεπόμενα πεδία. Το First Name και το Last Name δεν είναι διαθέσιμα για τροποποίηση.
4ΧρήστηςΥποβάλλει τις αλλαγές.
5FrontendΣτέλνει αίτημα PUT /cf_automation/users/update με τα δεδομένα του προφίλ.
6BackendΕπαληθεύει ότι το αίτημα προέρχεται από αυθεντικοποιημένο χρήστη.
7BackendΕλέγχει την εγκυρότητα των δεδομένων και τους κανόνες μοναδικότητας.
8BackendΕξασφαλίζει ότι το First Name και το Last Name δεν τροποποιούνται, ακόμη και αν περιλαμβάνονται στο request body.
9BackendΕνημερώνει αποκλειστικά τα επιτρεπόμενα στοιχεία του συγκεκριμένου χρήστη στη βάση δεδομένων.
10BackendΕπιστρέφει απόκριση επιτυχούς ενημέρωσης.
11ΣύστημαΕμφανίζει τα ενημερωμένα στοιχεία, διατηρώντας το αρχικό όνομα και επώνυμο.

4. Alternative / Error Flows

IDΠερίπτωσηΑναμενόμενη συμπεριφορά
AF-UPD-001Ενημέρωση χωρίς αυθεντικοποίησηΤο αίτημα απορρίπτεται.
AF-UPD-002Μη έγκυρα διαπιστευτήριαΔεν επιτρέπεται η ενημέρωση.
AF-UPD-003Προσπάθεια τροποποίησης First NameΤο αποθηκευμένο First Name παραμένει αμετάβλητο.
AF-UPD-004Προσπάθεια τροποποίησης Last NameΤο αποθηκευμένο Last Name παραμένει αμετάβλητο.
AF-UPD-005Αλλαγή email σε email άλλου χρήστηΗ ενημέρωση απορρίπτεται.
AF-UPD-006Μη έγκυρη μορφή emailΤο αίτημα απορρίπτεται λόγω validation.
AF-UPD-007Μη έγκυρη μορφή τηλεφώνουΤο αίτημα απορρίπτεται λόγω validation.
AF-UPD-008Προσπάθεια ενημέρωσης λογαριασμού άλλου χρήστηΔεν επιτρέπεται η μη εξουσιοδοτημένη τροποποίηση.
AF-UPD-009Ένα έγκυρο και ένα μη έγκυρο πεδίοΔεν αποθηκεύονται ανεπιθύμητες μερικές αλλαγές.
AF-UPD-010Αποτυχία αποθήκευσηςΤα προηγούμενα στοιχεία παραμένουν αμετάβλητα.

5. Business Rules

Rule IDBusiness Rule
BR-UPD-001Η ενημέρωση προφίλ απαιτεί αυθεντικοποίηση.
BR-UPD-002Επιτρέπεται μόνο η τροποποίηση των προβλεπόμενων πεδίων.
BR-UPD-003Το First Name παραμένει αμετάβλητο μετά την εγγραφή του χρήστη.
BR-UPD-004Το Last Name παραμένει αμετάβλητο μετά την εγγραφή του χρήστη.
BR-UPD-005Το email πρέπει να παραμένει μοναδικό.
BR-UPD-006Το email πρέπει να ικανοποιεί τον καθορισμένο RegEx κανόνα.

BR-UPD-008Ο χρήστης δεν επιτρέπεται να ενημερώνει λογαριασμό άλλου χρήστη χωρίς εξουσιοδότηση.
BR-UPD-009Η επιτυχής ενημέρωση πρέπει να αποθηκεύεται στη βάση δεδομένων.
BR-UPD-010Η αποτυχημένη ενημέρωση δεν πρέπει να προκαλεί ανεπιθύμητες μερικές αλλαγές.

6. Backend Functional Requirements

Requirement IDFunctional Requirement
API-UPD-001Η ενημέρωση προφίλ πρέπει να απαιτεί αυθεντικοποίηση.
API-UPD-002Ο χρήστης πρέπει να μπορεί να τροποποιεί τα προβλεπόμενα πεδία του λογαριασμού του.
API-UPD-003Το Backend δεν πρέπει να επιτρέπει την τροποποίηση του First Name μέσω του Update API.
API-UPD-004Το Backend δεν πρέπει να επιτρέπει την τροποποίηση του Last Name μέσω του Update API.
API-UPD-005Η αλλαγή email πρέπει να διατηρεί τη μοναδικότητα email στην εφαρμογή.
API-UPD-006Η αλλαγή email πρέπει να εφαρμόζει τον καθορισμένο RegEx.
API-UPD-007Η αλλαγή τηλεφώνου πρέπει να εφαρμόζει τον καθορισμένο RegEx.
API-UPD-008Η αλλαγή password, εφόσον υποστηρίζεται από αυτό το endpoint, πρέπει να εφαρμόζει τους προβλεπόμενους κανόνες.
API-UPD-009Ο χρήστης δεν πρέπει να μπορεί να ενημερώνει τον λογαριασμό άλλου χρήστη χωρίς εξουσιοδότηση.
API-UPD-010Μετά από επιτυχημένο Update, τα νέα επιτρεπόμενα στοιχεία πρέπει να είναι αποθηκευμένα στη βάση, χωρίς αλλαγή του First Name και του Last Name.
API-UPD-011Αποτυχημένη ενημέρωση δεν πρέπει να προκαλεί ανεπιθύμητες μερικές αλλαγές.

UC-004 — Document Upload / Document Creation

1. Περιγραφή

Το Use Case περιγράφει τη δημιουργία νέου εγγράφου στο Automation Platform. Το Backend υποστηρίζει τη δημιουργία εγγραφής εγγράφου χωρίς να είναι υποχρεωτική η άμεση μεταφόρτωση πραγματικού αρχείου. Ο χρήστης μπορεί αρχικά να δημιουργήσει έγγραφο με τίτλο, να το οργανώσει σε κατηγορία και να προσθέσει περιεχόμενο αργότερα μέσω Reupload. Όταν παρέχεται πραγματικό αρχείο, η επεξεργασία του γίνεται ασύγχρονα μέσω Parser Service. Μετά το parsing, το έγγραφο προβάλλεται ανάλογα με τον τύπο του, όπως Theory ή Quiz.

2. Βασικά στοιχεία

ΠεδίοΠεριγραφή
Use Case IDUC-004
Use Case NameDocument Upload / Document Creation
ActorΧρήστης
TriggerΥποβολή αιτήματος δημιουργίας εγγράφου
EndpointPOST /cf_automation/documents/upload
PreconditionsΗ εφαρμογή και το Backend είναι διαθέσιμα.
Success PostconditionΔημιουργείται νέα εγγραφή εγγράφου στη βάση δεδομένων, ακόμη και χωρίς πραγματικό αρχείο.
Failure PostconditionΔεν δημιουργείται ανεπιθύμητη εγγραφή εγγράφου.

3. Main Flow

ΒήμαActorΕνέργεια / Αναμενόμενη συμπεριφορά
1ΧρήστηςΞεκινά τη δημιουργία νέου εγγράφου.
2ΧρήστηςΟρίζει τον τίτλο του εγγράφου.
3Frontend / API ClientΥποβάλλει αίτημα δημιουργίας στο Backend.
4BackendΠαραλαμβάνει το αίτημα και ελέγχει τον υποχρεωτικό τίτλο.
5BackendΕλέγχει τους κανόνες μοναδικότητας τίτλου.
6BackendΔημιουργεί τη νέα εγγραφή εγγράφου στη βάση δεδομένων.
7BackendΔεν απαιτεί πραγματικό αρχείο για την αρχική δημιουργία της εγγραφής.
8BackendΕπιστρέφει απόκριση επιτυχούς δημιουργίας.
9ΣύστημαΤο έγγραφο είναι καταχωρισμένο και μπορεί να συσχετιστεί με κατηγορία ή να αποκτήσει περιεχόμενο μέσω Reupload.

AF-DOC-005Μη έγκυρα δεδομένα αιτήματοςΤο Backend επιστρέφει κατάλληλη απόκριση αποτυχίας.

BR-DOC-007Ένα έγγραφο χωρίς περιεχόμενο μπορεί να αποκτήσει αρχείο σε μεταγενέστερο στάδιο μέσω Reupload.

UC-005 — Document Reupload

1. Περιγραφή

Το Use Case περιγράφει τη μεταγενέστερη μεταφόρτωση ή αντικατάσταση του περιεχομένου ενός υπάρχοντος εγγράφου. Ο χρήστης επιλέγει ένα ήδη καταχωρισμένο έγγραφο και χρησιμοποιεί τη λειτουργία Reupload για να προσθέσει πραγματικό αρχείο ή να αντικαταστήσει το υπάρχον περιεχόμενο. Ισχύει τόσο για έγγραφα που δημιουργήθηκαν χωρίς αρχείο όσο και για έγγραφα με περιεχόμενο. Η επεξεργασία πραγματοποιείται ασύγχρονα και το αποτέλεσμα συνδέεται με την υπάρχουσα εγγραφή.
