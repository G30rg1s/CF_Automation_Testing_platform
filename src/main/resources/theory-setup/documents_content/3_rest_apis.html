REST και RESTful APIs

Για να καταλάβουμε τις έννοιες, χρησιμοποιούμε ως παράδειγμα ένα ηλεκτρονικό κατάστημα: βλέπουμε προϊόντα, αναζητούμε όσα μας ενδιαφέρουν και παρακολουθούμε τις παραγγελίες μας.

Τι είναι API

API σημαίνει Application Programming Interface. Είναι μια διεπαφή με συγκεκριμένους κανόνες, μέσα από την οποία ένα πρόγραμμα μπορεί να ζητήσει πληροφορίες ή ενέργειες από ένα άλλο πρόγραμμα.

Παράδειγμα: ανοίγουμε μια εφαρμογή καταστήματος και επιλέγουμε «Προϊόντα». Η εφαρμογή ζητά τη λίστα μέσω του API. Ο server επιστρέφει τα στοιχεία και η εφαρμογή τα εμφανίζει στην οθόνη. Το API ορίζει πώς γίνεται αυτό το αίτημα και τι απάντηση μπορούμε να περιμένουμε.

Τι είναι REST

REST σημαίνει Representational State Transfer. Είναι ένας τρόπος οργάνωσης της επικοινωνίας μεταξύ συστημάτων, βασισμένος σε συγκεκριμένες αρχές. Στο REST σκεφτόμαστε κυρίως σε πόρους: προϊόντα, χρήστες, παραγγελίες και άλλες πληροφορίες που θέλουμε να διαχειριστούμε.

Παράδειγμα: στο κατάστημά μας κάθε προϊόν έχει τη δική του διεύθυνση. Όταν ζητάμε το προϊόν 42, λαμβάνουμε μια περιγραφή του, όπως το όνομα, την τιμή και τη διαθεσιμότητα. Αυτή η περιγραφή είναι η αναπαράστασή του.

Τι σημαίνει RESTful

RESTful ονομάζουμε ένα API ή σύστημα που εφαρμόζει τις αρχές του REST. Με άλλα λόγια, REST είναι οι αρχές σχεδιασμού και RESTful είναι ο χαρακτηρισμός του συστήματος που τις ακολουθεί.

Για παράδειγμα, ένα API καταστήματος σχεδιάζεται γύρω από προϊόντα και παραγγελίες και εφαρμόζει τις αρχές που θα δούμε παρακάτω. Για να το χαρακτηρίσουμε πλήρως RESTful, εξετάζουμε συνολικά τον τρόπο λειτουργίας του.

Πώς συνδέονται REST και HTTP

Το HTTP καθορίζει τον τρόπο ανταλλαγής αιτημάτων και απαντήσεων στο Web. Το REST μας καθοδηγεί στο πώς οργανώνουμε αυτή την επικοινωνία. Στο κατάστημα, η εφαρμογή στέλνει το αίτημα με HTTP και ο σχεδιασμός REST καθορίζει πώς παρουσιάζονται και διαχειρίζονται οι πόροι.

Το HTTPS είναι η προστατευμένη μορφή επικοινωνίας HTTP. Το JSON είναι μία συνηθισμένη μορφή δεδομένων. Επομένως, άλλο είναι ο σχεδιασμός του API, άλλο η μεταφορά των μηνυμάτων και άλλο η μορφή των δεδομένων. Ένα API δεν γίνεται RESTful μόνο επειδή χρησιμοποιεί HTTP και JSON.

Πόροι και endpoints

Resource ή πόρος

Πόρος είναι κάτι που αναγνωρίζουμε και διαχειριζόμαστε μέσα από το API. Μπορεί να είναι ένας χρήστης, ένα προϊόν, μια παραγγελία ή μια συλλογή προϊόντων. Δεν είναι απαραίτητα ένας πίνακας ή μία εγγραφή βάσης δεδομένων.

Παράδειγμα: το τετράδιο με αναγνωριστικό 42 είναι ένας πόρος. Η λίστα με όλα τα προϊόντα του καταστήματος είναι επίσης ένας πόρος.

Representation ή αναπαράσταση

Αναπαράσταση είναι η περιγραφή ενός πόρου που μεταφέρεται από το σύστημα. Για το τετράδιο 42, η περιγραφή μπορεί να περιλαμβάνει το όνομα, την τιμή και το διαθέσιμο απόθεμα.

Ο πόρος είναι το προϊόν που διαχειριζόμαστε. Η αναπαράσταση είναι τα στοιχεία του που λαμβάνουμε. Αυτά μπορούν να σταλούν σε JSON, XML ή άλλη κατάλληλη μορφή· το REST δεν επιβάλλει μόνο μία.

Endpoint

Endpoint είναι ένα συγκεκριμένο σημείο πρόσβασης στο API, το οποίο καλούμε μέσω μιας διεύθυνσης. Μας δείχνει πού απευθυνόμαστε για έναν πόρο. Η λειτουργία εξαρτάται και από την HTTP μέθοδο με την οποία καλούμε αυτή τη διεύθυνση.

Παράδειγμα διεύθυνσης: https://api.example.com/products/42

https://api.example.com Εδώ βρίσκεται το API του υποθετικού καταστήματος /products Απευθυνόμαστε στη συλλογή των προϊόντων. /42 Προσδιορίζουμε το προϊόν με αναγνωριστικό 42.

Άρα, η διεύθυνση /products αφορά τη συλλογή, ενώ η /products/42 αφορά ένα συγκεκριμένο προϊόν της.

Path parameters

Είναι οι μεταβλητές τιμές μέσα στη διαδρομή. Στο /products/42, η τιμή 42 είναι το αναγνωριστικό του προϊόντος. Αν χρησιμοποιήσουμε /products/57, απευθυνόμαστε στο προϊόν 57.

Query parameters

Είναι πρόσθετες επιλογές μετά το σύμβολο ? στη διεύθυνση. Μπορούν να καθορίζουν φίλτρα, ταξινόμηση ή ποιο τμήμα μιας λίστας ζητάμε. Πολλές επιλογές χωρίζονται με το σύμβολο &.

Παράδειγμα: /products?category=books&page=2&limit=10

Το category=books περιορίζει τη λίστα στα βιβλία, το page=2 ζητά τη δεύτερη σελίδα και το limit=10 έως δέκα αποτελέσματα ανά σελίδα. Αυτή είναι η σημασία των παραμέτρων στο παράδειγμά μας· κάθε API ορίζει τις δικές του.

Οι βασικές αρχές του REST

1  Client και server

Ο client είναι η εφαρμογή που ζητά πληροφορίες ή ενέργειες. Ο server είναι το σύστημα που δέχεται το αίτημα και παρέχει την αντίστοιχη υπηρεσία. Καθένα έχει διαφορετικό ρόλο.

Παράδειγμα: στο κινητό επιλέγουμε να δούμε την παραγγελία μας. Η εφαρμογή είναι ο client. Το σύστημα του καταστήματος αναζητά την παραγγελία και επιστρέφει τα στοιχεία της. Αυτό είναι η πλευρά του server.

Ο διαχωρισμός μάς επιτρέπει να αλλάξουμε την εμφάνιση της εφαρμογής χωρίς να αλλάξουμε απαραίτητα τον τρόπο αποθήκευσης των παραγγελιών. Μπορούν επίσης διαφορετικοί clients, όπως η ιστοσελίδα και η εφαρμογή κινητού, να χρησιμοποιούν το ίδιο API.

2  Stateless επικοινωνία

Κάθε αίτημα περιέχει τις πληροφορίες που χρειάζεται ο server για να το καταλάβει. Δεν βασίζεται σε προηγούμενη συνομιλία που πρέπει να θυμάται ο server για τον συγκεκριμένο client.

Παράδειγμα: ζητάμε την παραγγελία 120. Στο αίτημα προσδιορίζουμε την παραγγελία και στέλνουμε τα απαιτούμενα στοιχεία πρόσβασης. Αν αργότερα ζητήσουμε την παραγγελία 121, το νέο αίτημα περιλαμβάνει ξανά όσα χρειάζονται.

Ο server δεν περιμένει να θυμάται ότι «πριν λίγο μιλούσαμε για τις παραγγελίες αυτού του χρήστη». Οι ίδιες οι παραγγελίες, όμως, παραμένουν αποθηκευμένες στη βάση δεδομένων. Stateless αφορά το πλαίσιο της επικοινωνίας, όχι την απουσία αποθηκευμένων δεδομένων.

3  Cacheability

Ορισμένες απαντήσεις μπορούν να αποθηκεύονται προσωρινά και να επαναχρησιμοποιούνται. Οι κανόνες της απάντησης καθορίζουν αν επιτρέπεται αυτό και για πόσο χρόνο.

Παράδειγμα: η λίστα με τις κατηγορίες του καταστήματος αλλάζει σπάνια. Ο server μπορεί να επιτρέπει την προσωρινή αποθήκευσή της για πέντε λεπτά. Αν τη χρειαστούμε ξανά μέσα σε αυτό το διάστημα, μπορούμε να χρησιμοποιήσουμε το αποθηκευμένο αντίγραφο, σύμφωνα με τους κανόνες της cache.

Έτσι μειώνονται τα αιτήματα και η αναμονή. Δεν αποθηκεύουμε υποχρεωτικά κάθε απάντηση: για άλλες πληροφορίες μπορεί να απαιτείται επανέλεγχος ή να απαγορεύεται η αποθήκευση.

Οι βασικές αρχές του REST

4  Uniform interface

Τα συστήματα επικοινωνούν με κοινούς, κατανοητούς κανόνες. Κάθε πόρος αναγνωρίζεται, τα μηνύματα περιγράφουν πώς διαβάζονται και ο client διαχειρίζεται τους πόρους μέσα από τις αναπαραστάσεις τους.

Παράδειγμα: η παραγγελία 120 έχει δική της διεύθυνση. Όταν τη ζητάμε, λαμβάνουμε τα στοιχεία της και πληροφορίες για τη μορφή τους, ώστε η εφαρμογή να μπορεί να τα διαβάσει.

Μέρος αυτής της αρχής είναι και το HATEOAS: η απάντηση καθοδηγεί τον client προς τις διαθέσιμες επόμενες ενέργειες, μέσω συνδέσμων ή άλλων στοιχείων υπερμέσων.

Παράδειγμα: μια απλήρωτη παραγγελία μπορεί να συνοδεύεται από σύνδεσμο πληρωμής. Μετά την πληρωμή, αυτή η επιλογή δεν προσφέρεται πλέον και μπορεί να εμφανίζεται σύνδεσμος για την απόδειξη. Έτσι οι διαθέσιμες ενέργειες συνδέονται με την τρέχουσα κατάσταση της παραγγελίας.

5  Layered system

Ανάμεσα στον client και στην υπηρεσία μπορούν να υπάρχουν ενδιάμεσα επίπεδα. Ο client επικοινωνεί με το σημείο πρόσβασης που γνωρίζει, χωρίς να χρειάζεται να ξέρει όλη την εσωτερική υποδομή.

Παράδειγμα: η εφαρμογή στέλνει αίτημα στο API του καταστήματος. Ένας load balancer, δηλαδή ένα σύστημα κατανομής αιτημάτων, το προωθεί σε έναν από τους διαθέσιμους servers. Η εφαρμογή συνεχίζει να χρησιμοποιεί την ίδια διεύθυνση.

Ένα άλλο ενδιάμεσο επίπεδο μπορεί να είναι μια cache που επιστρέφει επιτρεπόμενες αποθηκευμένες απαντήσεις. Τα επίπεδα πρέπει να διατηρούν τους συμφωνημένους κανόνες επικοινωνίας.

6  Code on demand

Αυτή η αρχή είναι προαιρετική. Ο server μπορεί να στέλνει κώδικα που εκτελείται στον client και του προσθέτει δυνατότητες.

Παράδειγμα: μια ιστοσελίδα καταστήματος κατεβάζει JavaScript που υπολογίζει δυναμικά μια ενδεικτική τιμή καθώς αλλάζουμε τις επιλογές ενός προϊόντος. Ένα REST API που παρέχει μόνο δεδομένα δεν χρειάζεται να χρησιμοποιεί αυτή τη δυνατότητα.

Μια συνηθισμένη σύμβαση σχεδιασμού

Συχνά δίνουμε στις διαδρομές ονόματα πόρων. Για παράδειγμα, /products για προϊόντα και /orders για παραγγελίες. Στο /orders/120 αναφερόμαστε σε μία συγκεκριμένη παραγγελία.

Η ενέργεια προσδιορίζεται και από την HTTP μέθοδο. Τα ουσιαστικά και ο πληθυντικός στα URLs βοηθούν στην οργάνωση, αλλά είναι σύμβαση σχεδιασμού και όχι ξεχωριστή υποχρεωτική αρχή του REST.

Βασικές διακρίσεις που θυμόμαστε

Authentication και authorization

Authentication είναι η ταυτοποίηση: ποιος κάνει το αίτημα. Authorization είναι ο έλεγχος δικαιωμάτων: τι επιτρέπεται να κάνει.

Παράδειγμα: συνδεόμαστε ως πελάτες στο κατάστημα. Η ταυτοποίηση επιβεβαιώνει ποιοι είμαστε. Ο έλεγχος δικαιωμάτων επιτρέπει να δούμε τις δικές μας παραγγελίες, αλλά όχι τις παραγγελίες ενός άλλου πελάτη.

Το REST δεν επιβάλλει έναν συγκεκριμένο τρόπο σύνδεσης. Ο μηχανισμός πρόσβασης επιλέγεται ανά σύστημα. Η χρήση HTTPS προστατεύει την επικοινωνία κατά τη μεταφορά.

JSON και REST

Το JSON είναι μορφή δεδομένων, ενώ το REST είναι τρόπος σχεδιασμού της επικοινωνίας. Όταν λαμβάνουμε στοιχεία προϊόντος σε JSON, γνωρίζουμε τη μορφή των δεδομένων. Αυτό μόνο του δεν αποδεικνύει ότι το API ακολουθεί όλες τις αρχές REST.

Τι περιέχει ένα response

Η απάντηση του server περιλαμβάνει status code, headers και, όπου προβλέπεται, body. Ο κωδικός περιγράφει το αποτέλεσμα, τα headers δίνουν πληροφορίες για την απάντηση και το body περιέχει τα δεδομένα ή πληροφορίες σφάλματος.

HTTP status και αποτέλεσμα της ενέργειας

Ο κωδικός απάντησης μάς βοηθά να καταλάβουμε τι συνέβη. Για παράδειγμα, όταν ζητάμε ένα προϊόν που δεν υπάρχει, το API μπορεί να απαντήσει με ένδειξη ότι ο πόρος δεν βρέθηκε και μια σύντομη περιγραφή του προβλήματος.

Σύντομη επανάληψη

Παράδειγμα από το κατάστημα

API: Η διεπαφή μέσω της οποίας η εφαρμογή ζητά προϊόντα και παραγγελίες. REST: Οι αρχές που καθοδηγούν την οργάνωση αυτής της επικοινωνίας. RESTful: Ο χαρακτηρισμός του συστήματος που ακολουθεί αυτές τις αρχές. Πόρος: Το προϊόν 42 ή η συλλογή των προϊόντων. Αναπαράσταση: Τα στοιχεία του προϊόντος που επιστρέφει το σύστημα, όπως όνομα, τιμή και διαθεσιμότητα. Endpoint: https://api.example.com/products/42 — το σημείο πρόσβασης στο προϊόν 42. Path parameter: https://api.example.com/products/42 — το 42 προσδιορίζει το συγκεκριμένο προϊόν. Query parameter: https://api.example.com/products?category=books&page=2&limit=10 — το category=books φιλτράρει τα βιβλία, το page=2 ζητά τη δεύτερη σελίδα και το limit=10 έως 10 αποτελέσματα ανά σελίδα.
