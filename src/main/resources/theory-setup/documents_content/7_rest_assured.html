REST Assured, Cucumber & Gherkin

Βασική θεωρία, δομή requests και παράδειγμα automation framework

1. Τι είναι το REST Assured

Το REST Assured είναι Java library για automation testing REST APIs. Μας επιτρέπει να δημιουργούμε HTTP requests, να στέλνουμε headers, query/path parameters και body, να λαμβάνουμε responses και να κάνουμε validations πάνω στο αποτέλεσμα.

Η πιο συνηθισμένη μορφή του ακολουθεί τη λογική BDD-style:

given() // request setup .when() // send HTTP request .then() // validations / extraction

2. Δομή ενός request

given(): προετοιμάζουμε το request — headers, authorization, content type, query params, path params και body.

when(): εκτελούμε τη HTTP method, π.χ. GET, POST, PUT, PATCH ή DELETE.

then(): μπορούμε να κάνουμε assertions ή να κάνουμε extract το response για να το ελέγξουμε αργότερα.

GET με query parameter

given() .queryParam("email", "nikos@test.com") .when() .get("/users") .then() .statusCode(200);

POST με headers, query param και body

given() .header("Authorization", "Bearer token") .contentType(ContentType.JSON) .queryParam("sendEmail", true) .body(requestBody) .when() .post("/users") .then() .statusCode(201);

3. ExtractableResponse και separation των validations

Σε μεγαλύτερα automation frameworks είναι συχνά πιο καθαρό να μην βάζουμε όλα τα assertions μέσα στο chained then(). Αντί γι’ αυτό, κρατάμε το response και το περνάμε σε ξεχωριστό validation layer.

ExtractableResponse<Response> response = given() .contentType(ContentType.JSON) .body(requestBody) .when() .post("/users") .then() .extract();

Μετά μπορούμε να χρησιμοποιήσουμε το response σε ξεχωριστή class για validations:

assertEquals(201, response.statusCode()); assertEquals("maria@test.com", response.jsonPath().getString("email"));

Η βασική ιδέα είναι separation of concerns: ο API client στέλνει requests, ενώ ο validator ελέγχει το response.

4. Παράδειγμα project structure

src/test/java ├── clients │ └── UserApiClient.java ├── models │ └── UserRequest.java ├── validators │ └── UserValidator.java ├── steps │ └── UserSteps.java └── runner └── CucumberTest.java src/test/resources └── features └── users.feature

5. Request Model / POJO

Αντί να γράφουμε raw JSON μέσα σε κάθε test, μπορούμε να έχουμε ένα Java object που αντιπροσωπεύει το request body.

public class UserRequest { private String username; private String email; private Integer age; private Boolean active; public UserRequest(String username, String email, Integer age, Boolean active) { this.username = username; this.email = email; this.age = age; this.active = active; } public String getUsername() { return username; } public String getEmail() { return email; } public Integer getAge() { return age; } public Boolean getActive() { return active; } }

6. API Client με REST Assured

Η client class είναι υπεύθυνη για τη δημιουργία και αποστολή των HTTP requests. Επιστρέφει το response χωρίς να φορτώνεται με business assertions.

import io.restassured.http.ContentType; import io.restassured.response.ExtractableResponse; import io.restassured.response.Response; import static io.restassured.RestAssured.given; public class UserApiClient { private static final String BASE_URL = "https://api.example.com"; public ExtractableResponse<Response> createUser(UserRequest request) { return given() .baseUri(BASE_URL) .contentType(ContentType.JSON) .body(request) .when() .post("/users") .then() .extract(); } public ExtractableResponse<Response> getUserByEmail(String email) { return given() .baseUri(BASE_URL) .queryParam("email", email) .when() .get("/users") .then() .extract(); } }

7. Validator Class

Η validator class συγκεντρώνει τα assertions. Έτσι τα tests και τα Cucumber steps παραμένουν πιο καθαρά και τα ίδια validations μπορούν να επαναχρησιμοποιηθούν.

import io.restassured.response.ExtractableResponse; import io.restassured.response.Response; import static org.junit.jupiter.api.Assertions.*; public class UserValidator { public void validateUserCreated( ExtractableResponse<Response> response, UserRequest expected) { assertEquals(201, response.statusCode()); assertEquals(expected.getUsername(), response.jsonPath().getString("username")); assertEquals(expected.getEmail(), response.jsonPath().getString("email")); assertEquals(expected.getAge(), response.jsonPath().getInt("age")); assertEquals(expected.getActive(), response.jsonPath().getBoolean("active")); } public void validateUserReturned( ExtractableResponse<Response> response, String expectedEmail) { assertEquals(200, response.statusCode()); assertEquals(expectedEmail, response.jsonPath().getString("email")); } }

8. Τι είναι Cucumber

Το Cucumber είναι εργαλείο που υποστηρίζει Behaviour-Driven Development (BDD). Διαβάζει executable specifications γραμμένες σε plain text και συνδέει τα βήματα των scenarios με πραγματικό automation code μέσω step definitions.

9. Τι είναι Gherkin

Το Gherkin είναι η γλώσσα/σύνταξη με την οποία γράφονται τα Cucumber scenarios. Τα αρχεία αποθηκεύονται συνήθως με κατάληξη .feature και χρησιμοποιούν λέξεις όπως Feature, Scenario, Given, When, Then, And και But.

Given: περιγράφει το αρχικό context / precondition.

When: περιγράφει την ενέργεια που εκτελείται.

Then: περιγράφει το αναμενόμενο αποτέλεσμα.

And / But: χρησιμοποιούνται για πιο φυσική συνέχεια των βημάτων.

10. Παράδειγμα Gherkin Feature

Feature: User API Scenario: Create a new user and retrieve it by email Given a new user with username "maria" and email "maria@test.com" When I create the user Then the user should be created successfully When I retrieve the user by email Then the correct user should be returned

Το feature file περιγράφει το business scenario με αναγνώσιμη μορφή. Δεν περιέχει REST Assured implementation details.

11. Step Definitions

Τα step definitions συνδέουν το Gherkin με τον Java automation code. Κάθε Given/When/Then αντιστοιχίζεται σε μία Java method.

import io.cucumber.java.en.Given; import io.cucumber.java.en.When; import io.cucumber.java.en.Then; import io.restassured.response.ExtractableResponse; import io.restassured.response.Response; public class UserSteps { private final UserApiClient userClient = new UserApiClient(); private final UserValidator userValidator = new UserValidator(); private UserRequest userRequest; private ExtractableResponse<Response> response; @Given("a new user with username {string} and email {string}") public void aNewUser(String username, String email) { userRequest = new UserRequest( username, email, 25, true ); } @When("I create the user") public void iCreateTheUser() { response = userClient.createUser(userRequest); } @Then("the user should be created successfully") public void userShouldBeCreated() { userValidator.validateUserCreated(response, userRequest); } @When("I retrieve the user by email") public void iRetrieveTheUserByEmail() { response = userClient.getUserByEmail(userRequest.getEmail()); } @Then("the correct user should be returned") public void correctUserShouldBeReturned() { userValidator.validateUserReturned( response, userRequest.getEmail() ); } }

12. Cucumber Runner

Χρειαζόμαστε και configuration/runner ώστε το test framework να γνωρίζει πού βρίσκονται τα feature files και τα step definitions. Η ακριβής μορφή εξαρτάται από το test runner και την έκδοση που χρησιμοποιούμε.

/* Ενδεικτική δομή runner/configuration */ Features: src/test/resources/features Glue / Step Definitions: steps Το runner εκτελεί τα .feature scenarios και το Cucumber αντιστοιχίζει κάθε step στην αντίστοιχη Java method.

13. Πώς συνδέονται όλα μαζί

users.feature ↓ Gherkin Scenario ↓ Cucumber Step Definitions ↓ UserApiClient ↓ REST Assured HTTP Request ↓ ExtractableResponse<Response> ↓ UserValidator ↓ Assertions

Έτσι έχουμε καθαρό separation:

Gherkin: περιγράφει το business scenario.

Step Definitions: συνδέουν τα business steps με Java code.

API Client: στέλνει τα HTTP requests.

Request Model: περιγράφει το request body.

ExtractableResponse: κρατά το response.

Validator: εκτελεί τα assertions.

14. Βασικό mental model

GIVEN → φτιάχνω test data / preconditions WHEN → καλώ το API THEN → κάνω validation στο response

Το Cucumber/Gherkin δεν αντικαθιστά το REST Assured. Το Gherkin περιγράφει το scenario, το Cucumber συνδέει τα steps με Java code και το REST Assured είναι αυτό που εκτελεί τα HTTP requests.
